# Дрончик: карта угроз БПЛА с прогнозом маршрута

Сервис читает публичные Telegram-каналы мониторинга и раскрашивает регионы России на карте MapTiler. Из отдельных фиксаций он собирает приблизительный маршрут БПЛА и прогнозирует, куда тот может долететь в ближайший час.

Обзор конкурентов лежит в [docs/COMPETITORS.md](docs/COMPETITORS.md).

## Как это работает

```
Telegram-каналы ──► parser.py ──► engine.py ──► WebSocket ──► карта (MapLibre + MapTiler)
   (Telethon)      события:        статусы регионов
                   тревога/отбой,  + tracker.py:
                   фиксация,       фиксации → трек → прогноз
                   курс, сбит
```

1. **Парсер** (`app/parser.py`) разбирает сообщения построчно. Он понимает склонения («над Курчатовым», «Брянской обл.», «Брянщина»), а также формулировки «курсом на X», «в сторону X», «Рыльск → Льгов», «на северо-восток», «2 БПЛА», «сбит» и «отбой». Регион из заголовка сообщения переносится на строки ниже. Для регионального канала можно задать регион по умолчанию.
2. **Газеттир** (`data/places.json`, `data/regions.geojson`) содержит 83 региона с границами и около 180 населённых пунктов с координатами. Новые города добавляются в JSON без правки кода.
3. **Трекер** (`app/tracker.py`):
   - одна и та же точка из разных каналов в пределах 6 минут считается одной фиксацией, но источники копятся;
   - новая фиксация пристёгивается к существующему треку, если до неё можно долететь со скоростью до 220 км/ч. Резкие развороты штрафуются;
   - курс берётся из заявленной цели («курсом на Курск»), иначе из пройденного пути, иначе из направления («на север»);
   - прогноз строится на 60 минут вперёд, с конусом неопределённости 10–30°. Скорость считается по фиксациям в диапазоне 60–220 км/ч, по умолчанию 150 км/ч;
   - регионы, в которые заходит конус, получают жёлтый статус «вероятный подлёт через ~N мин».
4. **Статусы регионов:** красный — ракетная опасность, оранжевый — угроза или фиксация БПЛА, жёлтый — на пути прогноза. Тревога снимается по «отбою» или сама через 2 часа без новых сообщений (ракетная — через 1 час), потому что каналы часто забывают писать отбой.
5. **Фронтенд** (`static/`): карта, список регионов под угрозой, цели с прогнозом, лента сообщений. Можно выбрать «Мою область», тогда при ухудшении обстановки придут уведомление браузера и звук. На телефоне панель становится нижней шторкой.

## Быстрый старт (демо, без Telegram)

```bash
pip install -r requirements-dev.txt
cp .env.example .env          # впишите MAPTILER_KEY
uvicorn app.main:app --port 8000
# открыть http://localhost:8000
```

Без настроенного Telegram запускается демо-сценарий налёта: время ускорено в 10 раз, полный цикл занимает около 9 минут.

## Боевой режим

1. Получите `api_id` и `api_hash` на https://my.telegram.org и впишите их в `.env`. Bot API читать чужие каналы не умеет, поэтому нужен пользовательский аккаунт. Лучше завести отдельный номер.
2. `cp channels.example.json channels.json` и перечислите каналы. Поле `region` — это id из `data/regions.geojson` для регионального канала, `null` — для общероссийского.
3. Один раз авторизуйтесь: `python -m app.telegram_login` (номер телефона и код из Telegram).
4. Поставьте `DEMO=0` и запустите `uvicorn app.main:app --host 0.0.0.0 --port 8000`.

Сообщения пишутся в SQLite (`data/dronchik.db`). После рестарта последние `HISTORY_HOURS` часов перечитываются, и карта восстанавливается.

Docker (вместе с Caddy, который выпускает HTTPS-сертификат для домена из `DOMAIN`):
```bash
docker compose run --rm dronchik python -m app.telegram_login   # один раз
docker compose up -d
```

Пошаговый запуск на своём домене и подключение мини-приложения Telegram описаны в [docs/DEPLOY.md](docs/DEPLOY.md).

### Другие источники

`POST /api/ingest` с заголовком `Authorization: Bearer $INGEST_TOKEN` и телом `{"channel": "...", "text": "..."}` прогоняет текст через тот же конвейер. Через него удобно подключить бота-пересыльщика, RSS или проверить парсер на реальных формулировках.

## API

| Метод | Что отдаёт |
|---|---|
| `GET /api/state` | Снимок: `regions` (статус, с какого времени, ETA), `tracks` (точки, прогноз, конус, регионы на пути), `feed` |
| `WS /ws` | Тот же снимок при каждом изменении и раз в 15 с |
| `GET /api/regions` | GeoJSON регионов |
| `POST /api/ingest` | Ручная подача сообщения |

## Что делать дальше

- **Калибровка парсера на реальных каналах.** У каждого канала свой стиль, поэтому стоит собрать выгрузку за неделю и прогнать её через `/api/ingest` или тесты.
- **Расширение газеттира районами и посёлками,** особенно в приграничных областях. Это сильнее всего влияет на точность маршрутов.
- **Telegram-бот для рассылки по регионам.** Конкуренты делают это первым делом, к тому же он работает при ограничениях мобильного интернета.
- **Регионы.** Границы взяты из открытого набора [click_that_hood](https://github.com/codeforamerica/click_that_hood) (83 субъекта). Чтобы добавить другие субъекты, подложите свой GeoJSON и пересоберите его скриптом `python scripts/build_regions.py путь/к/файлу.geojson` (нужны свойства `name` и `name_latin`).
- **Нагрузка.** Сейчас всё работает в одном процессе в памяти. Для тысяч одновременных пользователей нужно отдавать снимок через CDN/кэш или вынести WebSocket-рассылку в отдельный слой.

## Важно

Это оценка по открытым сообщениям, а не данные радаров. Маршрут показывает вероятное направление, а не точное положение цели. На сайте об этом есть дисклеймер, сохраните его.
